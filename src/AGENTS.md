# 前端架构约束

本文件适用于 `src/**`，补充根目录规则，仅定义结构、职责与依赖约束。

## 目录与职责

```text
src/
  main.tsx                 # 应用挂载与全局 Provider
  router.tsx               # 路由注册
  app/                     # 按需建立的应用组合层
  pages/                   # 路由入口，组合业务模块与 Page
  features/
    <feature>/
      index.ts             # 模块公开出口
      components/          # 该业务的组件
      hooks/               # 该业务的交互与数据协调
      api.ts               # 该业务的 IPC 适配与错误转换
      contracts.ts         # 与 Rust IPC DTO 对应的类型
      model.ts             # 前端展示模型与纯转换
      store.ts             # 确有共享需求的模块状态，可选
  components/
    ui/                    # CLI 生成的基础组件
    app-layout.tsx         # 全局壳层
    page.tsx               # 页面容器
  hooks/                   # 业务无关的共享 hooks
  lib/                     # 业务无关工具与传输适配
```

- 上述为职责映射，文件和目录按实际需要创建；不要求每个业务模块具有所有文件。
- `pages` 负责路由参数和展示组合，不承载持久化、IPC 细节或跨模块状态编排。
- 业务组件位于 `features/<feature>`；`components` 中的共享组件不依赖具体业务 store 或 API。现有生成 block 保持独立，业务接入使用组合与 props。
- 页面/壳层可以使用应用组合层或业务模块公开出口；应用组合层依赖业务模块公开出口，业务模块依赖共享能力。业务模块不得反向依赖应用组合层或页面，共享能力不得反向依赖这些上层。
- 模块内部使用内部文件引用，外部通过 `index.ts` 导入。跨业务依赖必须指向稳定公开接口，不能访问对方的 store、内部 hook 或组件实现。
- `app/` 仅在出现跨模块协调需求时建立，承载应用作用域的组合 hooks、协调器及必要的 Provider。例如切换工作区时，通过模块公开接口协调作用域切换、缓存失效和选择状态重置；不直接读写模块内部 store，不复制业务数据。
- 应用组合层只协调前端状态与交互，不承担业务事务。涉及多个业务资源的一致性操作由 Rust 应用服务完成，前端不能通过串联多个写入 command 冒充原子操作。

## 组件边界

- 展示组件通过 props 接收数据，通过回调表达用户意图，不隐藏请求、路由跳转或全局状态写入。
- 业务容器或 hooks 负责请求、状态协调和副作用；拆分以独立职责为依据，不机械拆分每个 JSX 片段。
- 组件 API 使用明确的业务类型，不以大量布尔开关承载互斥模式；互斥状态使用可区分联合类型。
- 业务逻辑不进入基础 UI 组件；单个业务的特殊样式和交互留在业务模块。

## 状态管理

| 状态 | 所有者与约束 |
| --- | --- |
| 弹窗、展开、临时输入 | 就近组件的 React state 或 reducer |
| 可分享的筛选、分页、选中资源 | 合适时使用路由参数或查询参数作为来源，不与 store 双向维护副本 |
| 编辑草稿 | 表单或业务模块所有，提交成功前不冒充已持久化数据 |
| Rust 查询结果 | 业务模块的数据访问层或统一查询缓存管理，不复制到另一全局 store |
| 模块内跨组件交互 | 模块作用域的 Context/reducer 或专用 store，按订阅需求选择 |
| 主题等应用级 UI 偏好 | 专用全局 Provider 或 store，不夹带项目、任务等业务数据 |

- Context 适合依赖注入和低频共享状态；高频变化的状态采用细粒度订阅，避免无关组件随整个全局对象更新。
- 缓存键包含完整数据作用域，如工作区 ID、资源 ID、筛选和分页条件；不能仅以命令名作为所有查询的键。
- 写入成功后更新或失效相关列表、详情和汇总缓存；失败保留可恢复的草稿。乐观更新必须具备失败回滚及并发冲突处理。
- 请求状态区分未加载、加载中、成功和失败；已有数据的后台刷新不得被误判为空数据。成功空列表与请求失败不可混用。
- 旧请求响应按请求标识或作用域丢弃；重复点击不能产生不受控的重复写入。自动重试遵循根目录的幂等约束。
- 事件与 channel 订阅有明确所有者和释放时机，兼容 React StrictMode 的重复挂载清理；异步注册在卸载后才完成时也必须释放。
- 单纯浏览器运行时明确表达桌面能力不可用；不得静默使用模拟成功、空数据或 localStorage 替代 Rust 业务行为。显式演示模式与真实数据隔离。
